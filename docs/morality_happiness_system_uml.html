05Agent 决策 Prompt 与权限

系统为每位 Agent 组装当前情境、个体状态和同轮已决策摘要，要求输出一个紧凑 JSON 对象。模型只提出行为参数；生产、交易、分配及状态更新由仿真执行。

输入上下文

情境 sc / 上下文 ctx情境、行动模式、匮乏压力、机会、集体化；轮次、群体规模、缺粮率、先前决策摘要。
个体 ag道德类型与权重、能力、需求、幸福感、储备、疲劳、身份、贝壳、状态与小组。

标准 Prompt 的固定指令摘录

Return exactly one compact JSON object. No markdown, no prose, no extra keys. Template: {"participation_action":0.9,"effort":0.6, "compliance_action":0.7,"share_rate":0.5, "restraint_rate":0.2,"reason":"fit"}. First five values are numbers in [0,1]. reason: survival | fit | fair | fatigue | reserve | belong. If Extreme_Fatigue: effort=0, restraint_rate>=0.7. Data: {sc, ctx, ag}

调用与容错

  • Agent 按顺序决策；标准 Prompt 最多提供先前 12 人的摘要。
  • 中国科技云通路使用紧凑版本，先前决策摘要最多 4 人。
  • 模型返回需解析、数值归一化；失败可重试，耗尽后使用规则兜底并记录来源。
  • 规则模式不调用外部模型；模型是否可用与仿真是否持续运行分别记录。

来源：simulation.py / _agent_decision_prompt、_compact_agent_decision_prompt、_llm_decide

07身份、分成与周期评选

首领 Chief全体一个
酋长 Chieftain定额席位
猎人 Hunter按容量分配至酋长

默认制度

等级权重 4 : 2 : 1；首领领导份额 10%；酋长席位 7、每席猎人容量 16。等级分成与晋升均可通过参数开关控制。

每 28 轮评选：贝壳持有量百分位 × 0.8 + 当期狩猎贡献百分位 × 0.2；平分时使用固定种子产生的排序依据，并支持最低任期。

首个评选周期被标注为 warm-up。身份变化后重新分配上下级关系；评选结果写入 promotion reviews / events。

来源：simulation.py / _initialize_hierarchy、_evaluate_promotions；config.py

03单 tick 执行流程

1 救济与准备库存起点；兑现上一轮待救济；更新压力 / 分组
2 个体决策按 Agent 顺序执行规则或 LLM；汇总行为
3 狩猎与分配按总体 / 抱团 / 个体模式产出并分配
4 市场交易按供需撮合，交换食物与贝壳
5 消费与状态实际消费、库存上限、缺粮与疲劳
6 幸福与道德幸福评分、道德一致性与权重适应
7 账本与日志记录指标、事件、交易和守恒账本
8 定期评选到评选周期时更新角色和上下级

04个体状态与资源闭环

Normal 正常 食物不足 → Extreme_Fatigue 极度疲劳 → 下一轮按配置兑现救济；本轮消费满足需求后可恢复 Normal。

食物账本：期初库存 + 生产 + 外部救济 − 消费 − 损耗 − 期末库存；贝壳在买卖双方之间转移。公共粮仓救济为内部转移，不重复计为外部输入。

11接口、导出与实现审计

HTTP 接口

GET /api/defaults · /api/scenarios · /api/llm-traces
POST /api/run · /api/run-stream · /api/stop
POST /api/model-test · /api/llm-traces/clear

流与导出

run-stream 返回 NDJSON 事件，前端展示日志与指标并导出实验 JSON。run 返回批次结果；多重复聚合存在记录截取。

实现边界

  • 环境、交易、分配、状态和幸福评分由 Python 本地实现。
  • Agent 提示词产生行为参数，不直接改写环境状态。
  • 模型失败时可局部回退规则；结果中的来源与日志应一并检查。
  • 情境供给比为目标值；实际产出受行动和组织效率影响。
